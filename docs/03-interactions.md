| INT-02 | UC-02 | Браузер → Chat | Текст ответа и ID сессии | Сохранённое сообщение и ответ агента | POST /api/chat/messages | Повтор запроса не дублирует сообщение |
| INT-03 | UC-02 | Chat → Оркестратор | История, текущий профиль, стадия интервью | Следующий вопрос или предложение завершить | Внутренний вызов | Ограничение длины контекста и числа шагов |

## Сквозной порядок

1. Пользователь входит и отвечает агенту.
2. Backend сохраняет ответ до обращения к LLM.
3. LLM предлагает вопрос и факты; пользователь подтверждает профиль.
4. Backend создаёт редактируемое резюме, затем экспортирует PDF.
5. Фоновая загрузка независимо обновляет вакансии.
6. Matching сравнивает профиль с сохранёнными вакансиями.
7. Gap-анализ передаёт реальные пробелы модулю обучения.

## Взаимодействия команды

| Кто | Передаёт кому | Артефакт | Когда |
|---|---|---|---|
| Ведущий | Frontend и данные | Схемы API и примеры JSON | До параллельной реализации |
| Данные | Ведущий и QA | Fixture вакансий, словарь навыков, ожидаемые совпадения | До matching |
| Frontend | QA | Работающие страницы и состояния ошибок | Каждый завершённый сценарий |
| QA | Вся команда | Шаги воспроизведения, ожидаемый / фактический результат | После каждого сценария |
| Каждый | Ведущий | Небольшой PR с описанием и проверкой | По завершении задачи |
