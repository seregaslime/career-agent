# Структурный профиль и факты из интервью

Профиль состоит из основных полей (имя, желаемая роль, формат работы, город, краткие сведения) и структурных записей: навыки, проекты, опыт и образование. Факты из интервью добавляются в профиль автоматически, без подтверждения; пользователь может изменить или удалить любую запись. Резюме и подбор вакансий используют записи со статусом `confirmed` — сейчас это все записи профиля.

## Как факт попадает в профиль

1. Пользователь отвечает в интервью. Backend сохраняет сообщение до вызова модели.
2. Получив ответ агента, браузер делает второй запрос к той же модели с отдельной инструкцией извлечения. Модель видит только предыдущий вопрос агента (как контекст) и текущий ответ пользователя. Возвращает JSON `{"facts": [...]}`.
3. Браузер разбирает JSON, отбрасывает неизвестные виды и поля, обрезает строки до лимитов сервера. Не более 10 фактов.
4. Backend (`POST /api/profile/items/extracted`) повторно проверяет схему и принимает факт, только если его цитата `evidence` дословно (без учёта регистра, пунктуации и «ё») встречается в сохранённом сообщении этого пользователя. Иначе факт пропускается с причиной `evidence`. Дубликаты существующих записей пропускаются с причиной `duplicate`.
5. Принятые факты сразу сохраняются со статусом `confirmed` и источником `interview` и видны в профиле с пометкой «из интервью» (при наведении — цитата). Пользователь может изменить или удалить любую из них.

Сообщение обрабатывается один раз: повторный запрос по тому же сообщению возвращает уже созданные предложения (`already_processed: true`) и не создаёт дубликатов. Сбой модели или неверный JSON не отменяет сохранённый диалог. Браузер сразу повторяет извлечение один раз; если и это не удалось, сообщение обрабатывается автоматически после следующего ответа агента (не более трёх необработанных сообщений за раз, включая созданные до этой версии). Кнопок для ручного поиска фактов нет.

Проверка цитаты не доказывает, что модель правильно поняла смысл. Она отсекает факты, которых пользователь не говорил. Неточные записи пользователь исправляет или удаляет в профиле.

## Виды записей

| Вид | Обязательное поле | Остальные поля |
|---|---|---|
| skill | name (до 80) | level: beginner, intermediate, advanced или null |
| project | title (до 120) | role (120), technologies (до 20 по 60), description (1000) |
| experience | position (до 120) | organization (120), period (60), description (1000) |
| education | institution (до 160) | program (160), period (60) |

Дубликаты определяются по нормализованному ключу: название навыка или проекта, должность и организация, учебное заведение и направление. Отклонённые записи не мешают добавить такую же запись снова. Лимит — 300 записей на пользователя.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/profile/items?status= | Свои записи; по умолчанию без отклонённых |
| POST | /api/profile/items | `{kind, data}` — ручная запись, сразу `confirmed` |
| PATCH | /api/profile/items/{id} | `{data}` — правка записи |
| DELETE | /api/profile/items/{id} | Удалить свою запись |
| POST | /api/profile/items/extracted | `{turn_id, facts}` — сохранить в профиль факты модели по своему сообщению |

Чужие записи и сообщения возвращают 404. Лишние поля запрещены. Ответы не кешируются. `GET /api/chat` возвращает признак `facts_checked` для каждого сообщения. `PATCH /api/profile` дополнительно принимает `work_format` (`''`, office, remote, hybrid, any) и `location`.

Миграция `0007_profile_items` добавляет таблицу `profile_items`, поля `profiles.work_format`, `profiles.location` и `chat_turns.facts_checked_at`. Существующие данные не меняются. Миграция `0008_auto_confirm_facts` переводит ранее предложенные (`suggested`) записи в `confirmed`; статусы `suggested` и `rejected` остаются в схеме только для старых данных. Текстовые поля «образование» и «о себе» остаются как краткое описание.

## Ограничения версии

- Извлечение расходует второй запрос к модели пользователя на каждое сообщение.
- Истории версий профиля нет: хранится текущее состояние каждой записи и время изменения.
- Ошибочно понятый моделью факт попадает в профиль сразу; его нужно исправить или удалить вручную.
- Перед будущим резюме нужна отдельная проверка, что в него попадают только `confirmed`-записи.
