# Техническая основа

Решения предварительные: при старте реализации зафиксировать версии зависимостей и проверить документацию выбранных библиотек.

- Web: React + TypeScript + Vite.
- Backend: Python + FastAPI, один модульный монолит.
- БД: PostgreSQL; SQLAlchemy и Alembic для модели и миграций.
- Агент: один оркестратор и интерфейс LLMProvider с mock- и real-реализациями. Конкретного платного провайдера пока не выбираем.
- Вакансии: интерфейс VacancySource, demo-источник и один реальный адаптер после проверки доступности API и его правил.
- Matching v0: нормализованные навыки, явные фильтры и прозрачные веса. Векторный поиск вводить после измерения ограничений базового варианта.
- PDF: выбрать библиотеку отдельным техническим экспериментом по проверке кириллицы, переноса строк и установки в контейнере.
- Разработка и демонстрация: Docker Compose, отдельные .env.example и конфигурация demo-режима.

Redis, брокер очередей, графовая и векторная БД, микросервисы и несколько агентов MVP не требуются. Обновление вакансий сначала запускается отдельной командой, затем по расписанию.

## Модули и сущности

| Модуль | Сущности |
|---|---|
| Auth | User, Session |
| Chat | Conversation, Message |
| Profile | Profile, Education, Experience, Project, Skill, ProfileSkill |
| Resume | Resume, ResumeVersion |
| Vacancies | Vacancy, VacancySkill, ImportRun |
| Learning | LearningPlan, LearningStep |

Для пользовательских сущностей обязателен owner_id. У навыка профиля хранятся источник, статус подтверждения и при наличии доказательство. Требования вакансии различают обязательные и желательные навыки. Зарплата хранится вместе с валютой, периодом и gross/net, если известны; неизвестные величины не сравниваются напрямую.

## Проверки качества

Unit: нормализация навыков, scoring, валидация фактов. Integration: БД, авторизация, изоляция пользователей, API. Сквозная приёмка: интервью → профиль → PDF → вакансии → план. Отдельные проверки: LLM timeout, неверный JSON, prompt injection в тексте вакансии как недоверенные данные, пустая выдача и повтор импорта.

## Работа с Git

Основная ветка main; задачи в feature-ветках и небольших PR. Ключи — только в локальном окружении. Не добавлять лицензию без решения команды о разрешённых условиях использования. Публичность репозитория сама по себе не означает выбранную open-source лицензию.
