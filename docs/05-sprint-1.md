# Первый спринт: воспроизводимый каркас

Цель: поднять frontend, backend и PostgreSQL и подтвердить, что интерфейс получает ответ API. Реализация этого спринта — следующий шаг; сейчас подготовлен его backlog.

| ID | Задача | Владелец | Критерий готовности | Зависимость |
|---|---|---|---|---|
| S1-01 | Создать backend FastAPI, настройки окружения и GET /api/health | Ведущий | Ответ 200 с состоянием приложения; есть проверка endpoint | — |
| S1-02 | Подключить PostgreSQL, SQLAlchemy и Alembic | Ведущий | Первая миграция применяется к пустой БД; ошибка подключения диагностируется | S1-01 |
| S1-03 | Сделать Docker Compose и .env.example | Ведущий | Команда из README запускает сервисы без ручного редактирования исходников | S1-01,02 |
| S1-04 | Создать React/TypeScript frontend с маршрутизацией | Участник 2 | Страницы чат, профиль, резюме, вакансии доступны как заготовки | — |
| S1-05 | Показать состояние API в интерфейсе | Участник 2 + ведущий | Видны состояния загрузки, успеха и ошибки подключения | S1-01,04 |
| S1-06 | Подготовить 20 синтетических вакансий и 3 профиля | Участник 3 | Разные роли и стеки, обязательные / желательные навыки, пропуски зарплаты; без реальных личных данных | Контракт из технического документа |
| S1-07 | Составить чек-лист приёмки и журнал дефектов | Участник 4 | Проверены запуск, недоступный API, повторный запуск и инструкция новичка | S1-03,05 |
| S1-08 | Добавить CI с lint и минимальными проверками | Ведущий | Проверки автоматически запускаются на PR; воспроизводимы локально | S1-01,04 |

## Порядок для ведущего, если остальные временно недоступны

S1-01 → S1-02 → S1-03 → минимальные S1-04/05 → S1-08. Данные и полный интерфейс не должны задерживать запуск основы.

## Приёмка спринта

Чистый checkout, заполнение .env по примеру, запуск по README. Страница показывает доступность backend. Backend подключается к БД; миграции применяются. Остановка backend приводит к понятному состоянию ошибки интерфейса. После рестарта всё работает снова. В репозитории нет настоящих ключей.

## После спринта

Начать вход и профиль: сначала модель User/Profile и миграции, затем API с проверкой владельца, затем UI. Интервью строить поверх работающего хранения профиля.
