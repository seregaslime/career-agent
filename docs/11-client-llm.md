# Интервью с моделью пользователя

/chat — вход обязателен. История хранится в PostgreSQL отдельно для каждого пользователя. Модель вызывается браузером, а не сервером Render. Локальные модели не становятся доступны другим пользователям сайта.

Поле сообщения становится доступно после загрузки истории из аккаунта Career Agent. API-ключ провайдера не заменяет вход в приложение. При отсутствии входа или сбое backend причина остаётся видна независимо от настроек модели. Можно войти в новой вкладке и нажать «Повторить проверку входа и истории» в исходной вкладке: введённый ключ и выбранная модель сохранятся в её памяти. Проверка истории ограничена 30 секундами; после сбоя доступен ручной повтор без перезагрузки страницы. У кнопки отправки показывается, чего не хватает: входа, адреса, ключа Groq или модели.

## Ollama

1. Запустить Docker Ollama с опубликованным только на loopback портом, например 127.0.0.1:11434:11434. Сохранить том моделей.
2. Указать OLLAMA_ORIGINS=https://career-agent-9pq.pages.dev (для разработки добавить конкретный localhost origin). OLLAMA_HOST внутри Docker — 0.0.0.0:11434. Не публиковать модель в интернет.
3. Открыть /chat, проверить подключение, выбрать модель из /api/tags. Разрешить браузеру доступ к локальному ПО, если он запросит.
4. Отправить сообщение выбранной модели.

Подключение к произвольным LAN-адресам в этой версии не поддерживается, только localhost/127.0.0.1/[::1]. Вне Docker настройки OLLAMA_HOST могут отличаться.

## Внешний API

Каждый пользователь использует собственный аккаунт и ключ провайдера. Общего ключа Career Agent нет. Режим совместимого API поддерживает OpenAI Chat Completions: GET /models и POST /chat/completions. Указывается базовый адрес, обычно с /v1, без /chat/completions. Допускается HTTPS либо loopback HTTP. Провайдер должен поддерживать CORS для нашего сайта: серверный прокси в этой версии отсутствует. Это не поддержка всех существующих API: сервисам с другим форматом авторизации или сообщений потребуется отдельный адаптер.

### Groq

1. В /chat выбрать «Совместимый API (прямой запрос)» и провайдера Groq.
2. Создать личный ключ в [Groq Console](https://console.groq.com/keys) и вставить его в поле API-ключ. Не отправлять ключ в чат, GitHub или настройки frontend-деплоя.
3. Адрес заполняется автоматически: https://api.groq.com/openai/v1. Проверить подключение, выбрать модель из полученного списка или вписать вручную. Начальная модель — qwen/qwen3.8-27b; доступность зависит от аккаунта и каталога Groq.
4. Отправить сообщение. Вместо дополнительного чекбокса показано предупреждение: сообщения и контекст расходуют токены и квоту личного API, стоимость зависит от тарифа провайдера. Полученный список моделей подтверждает доступ к каталогу, но не успешную генерацию.

Для Groq используется max_completion_tokens=700; для начальной Qwen отключены рассуждения через reasoning_effort=none, чтобы бюджет короткого интервью не уходил на скрытый вывод. Эти параметры не добавляются запросам к другим провайдерам. Основание — [совместимость Groq](https://console.groq.com/docs/openai) и [настройки рассуждений](https://console.groq.com/docs/reasoning), проверенные 20 ноября 2026.

### Другой совместимый API

Выбрать «Другой совместимый API», ввести базовый адрес, личный ключ (если требуется) и идентификатор модели. Если /models не поддерживается, модель можно вписать вручную и отправить сообщение без проверки каталога. Произвольный адрес может иметь дополнительный путь, например https://provider.example/api/v1. Обычные API получают max_tokens=700; совместимость иных параметров зависит от провайдера.

Ошибки доступа 401/403, неверного адреса или модели 404 и квоты 429 показываются отдельно. При 429 отображается Retry-After, если браузер имеет доступ к этому заголовку; иначе предлагается ручной повтор позднее. Автоматических повторов нет. Незавершённое сообщение остаётся в истории; при повторе не создаётся дубликат. Обрезанный по лимиту ответ (finish_reason=length) не сохраняется как завершённый.

API-ключ хранится только в памяти компонента до ухода со страницы. Он отправляется исключительно выбранному API в Authorization, не передаётся backend Career Agent, не сохраняется в БД/localStorage/sessionStorage. Cookies не передаются модели; перенаправления запрещены. Смена провайдера, режима или адреса очищает ключ. Ключ можно очистить отдельной кнопкой. Контекст последних 20 пар передаётся при явной отправке сообщения или ручном повторе; об этом сообщается в интерфейсе.

## Сохранение и ограничения

Сначала сохраняется вопрос пользователя, затем вызывается модель; сбой не теряет сохранённый текст. Неполученный ответ можно запросить повторно, в том числе после перезагрузки. Если ответ получен, а сохранение не удалось, до закрытия страницы он остаётся в памяти и можно повторить только сохранение. У каждого сообщения клиентский UUID для безопасного повтора записи. Сохранённые ответы не перезаписываются.

Контекст модели — последние 20 пар вопрос/ответ (до 40 сообщений) и инструкция, вся история хранится отдельно. Ограничения: 200 пользовательских сообщений интервью, 4000 символов вопрос, 16000 символов ответа, ожидание модели до 3 минут. Лимит 200 сообщений пока без архивации/нового интервью. Ответы выводятся как текст, без исполнения HTML, команд или инструментов. Они не меняют профиль автоматически: найденные факты сохраняются только как предложения ([docs/12-profile-facts.md](12-profile-facts.md)).

Точный подсчёт и сжатие токенов ещё не реализованы. 20 пар могут превысить квоту Groq: история ограничена количеством сообщений, а не 8000 токенами. Лимит токенов в минуту делит вход и выход и может применяться ко всему аккаунту провайдера, даже при нескольких ключах. Квоты разных пользовательских аккаунтов не объединяются приложением.

Этап 3 включает чат, сохранение, подключение модели и извлечение фактов. После ответа агента браузер делает второй запрос к модели и отправляет найденные факты на сервер; подкреплённые цитатой сразу добавляются в профиль, где их можно изменить или удалить. Для сохранённых ответов нельзя доказать, что они созданы конкретной моделью: клиентские данные считаются недоверенными.

## Проверки

Тесты используют детерминированные ответы вместо реальных LLM. Проверяются владельцы сообщений, повтор записи, незавершённый ответ, изоляция аккаунтов, отсутствие изменений профиля, адаптеры Ollama/API, CORS/HTTP ошибки, отсутствие cookies и запрет redirect. Отдельная ручная проверка локальной Ollama не заменяет CI.
