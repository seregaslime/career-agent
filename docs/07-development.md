# Рабочее пространство и качество

## Что настроено

- AGENTS.md: общий договор работы, ревью, тестов, данных и деплоя. CLAUDE.md отсылает к нему.
- Python 3.9+ для служебных скриптов; CI проверяет их на Python 3.12. Версии приложения фиксируются при создании каркаса.
- .editorconfig: UTF-8, LF, единые отступы.
- python3 scripts/check.py: проверка относительных Markdown-ссылок, запрещённых имён секретных файлов, пробелов в diff и тесты инструментов. Это не полноценный сканер секретов и не тесты приложения.
- .githooks/pre-push: проверки, чистое рабочее дерево, запрет прямого push в main, запись ревью для отправляемого SHA. Разрешены branch pushes текущего HEAD; tags требуют отдельного будущего release-процесса.
- CI / Repository checks: тот же набор на GitHub для PR и рабочих веток.
- Dependabot: еженедельные обновления GitHub Actions, версии actions закреплены SHA.
- Шаблоны PR и задач, CODEOWNERS для назначения владельца.
- На GitHub включена защита main: только PR, обязательный Repository checks на актуальной базе, закрытие обсуждений, запрет force-push и удаления; правило действует и для администратора. Число обязательных одобрений — 0, чтобы не блокировать работу одного разработчика.
- GitHub Secret Scanning и Push Protection включены: распознаваемые ключи проверяются сервером. Это не гарантирует обнаружения любого секрета.

## Подготовка нового компьютера

```sh
git clone https://github.com/seregaslime/career-agent.git
cd career-agent
python3 scripts/setup.py
python3 scripts/check.py
```

Установка hook делается в каждом clone. Скрипт не перезаписывает чужой core.hooksPath. Hooks — локальная дисциплина, их можно обойти; серверный барьер даёт защита main с обязательным CI.

## Рабочий цикл

```sh
git switch -c codex/short-task
# Сделать небольшую задачу и meaningful tests.
python3 scripts/check.py
git diff
# Проверить весь diff относительно origin/main, затем commit.
git add <нужные-файлы>
git commit -m "feat: short description"
python3 scripts/review.py record --reviewer 'имя или agent:self' --summary 'Что проверено; оставшиеся ограничения'
git push -u origin HEAD
```

После этого открыть PR и дождаться CI. Запись ревью хранится только внутри .git/career-reviews, не отправляется в репозиторий. Для команды краткий результат ревью нужно указать в PR. Запись подтверждает факт заявленного просмотра, но не доказывает его качество. Саморевью не считается независимым. При новом commit/amend нужна новая запись; отдельное ревью товарища желательно перед merge.

## Проверки по мере реализации

| Компонент | Инструменты | Что проверять |
|---|---|---|
| Backend | Ruff, type checker, pytest | API, схемы, ошибки, права владельца |
| PostgreSQL | Отдельная БД сервиса в CI | Миграция на пустую БД, ограничения, репозитории |
| Frontend | ESLint, TypeScript, Vitest + Testing Library | Формы, состояния загрузки и ошибок, отображение API |
| Сборка | npm ci, production build | Lockfile и реальная сборка frontend |
| Сквозные сценарии | Playwright | Интервью → профиль → резюме → подбор → обучение |
| Агент | Фиксированные fixtures и mock LLM | Неверный JSON, таймаут, неподтверждённые факты |

Эти проверки приложения пока не установлены: исходников ещё нет. Добавлять вместе с соответствующим компонентом, без passWithNoTests и фиктивных зелёных jobs. Онлайн smoke-тест LLM — отдельный ручной запуск с бюджетом, не обычный PR CI.

## CI/CD и бесплатный хостинг

Целевая схема: feature → локальные проверки и ревью → PR → CI → merge в main → deploy проверенного SHA → smoke test.

Frontend — Cloudflare Pages; backend — Render Free; БД — Neon Free. Постоянный PostgreSQL не запускается внутри CI: там только временная тестовая БД.

CD подключается вместе с каркасом приложения:

1. Настроить отдельные проекты хостинга и переменные окружения. Настоящий DATABASE_URL хранится только в backend-секретах.
2. Добавить health/readiness endpoint, настройки CORS и корректный URL API для frontend.
3. Зафиксировать команды сборки, запуска и миграций; проверить миграции на тестовой БД.
4. Настроить выпуск из GitHub Actions после успешного CI на main. Checkout должен использовать SHA прошедшего CI; запрещено checkout плавающего main из workflow_run без проверки SHA. Деплой fork PR не получает секретов.
5. Исключить параллельный негейтированный автодеплой провайдера, который обходит GitHub CI.
6. Деплой frontend через Cloudflare Pages API/CLI, backend — через Render API с привязкой к проверенному commit. Секреты ограничить проектом; deploy jobs не работают на PR.
7. Сначала миграции по выбранной безопасной стратегии, затем backend и frontend; проверить health и один запрос к БД. Сохранять предыдущий deploy для отката приложения; откат схемы не считать автоматическим.

Сейчас workflow деплоя и облачные ресурсы не созданы. Без приложения и доступов нельзя честно проверить CD. Бесплатные лимиты и засыпание сервисов учесть при smoke-тесте; собственный домен не требуется.

## Навыки и интеграции

| Инструмент | Для чего | Решение |
|---|---|---|
| GitHub | Репозиторий, PR, Actions | Уже используется |
| Neon | БД и ветки БД | Подключить перед первым деплоем; production не создавать автоматически при подключении |
| Render | Backend и диагностика | Подключить перед первым деплоем |
| Graphify | Анализ связей растущего проекта | Уже доступен; полезен позднее, не нужен для пустого каркаса |
| OpenAI Docs | Официальная документация при подключении OpenAI | Уже доступен; LLM-провайдер пока не выбран |
| Documents / Presentations | Отчёт и защита | Уже доступны; использовать ближе к защите |

Отдельный навык под проект сейчас не требуется: правила живут в AGENTS.md, команды — в репозитории и CI. Не устанавливать плагины «на всякий случай». GitHub review товарища и обычное ревью diff важнее количества AI-инструментов.
