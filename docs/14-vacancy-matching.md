# Подбор вакансий по профилю: первая версия

На странице вакансий кнопка «Подобрать по моему профилю» включает `match=profile`.
Браузер читает собственный профиль и подтверждённые записи через существующие
защищённые API. До успешной загрузки обоих источников вакансии не ранжируются.
Обычный публичный поиск по-прежнему работает без входа и не читает профиль.

## Поиск и сравнение

1. Поиск заполняется желаемой должностью; если её нет — первым навыком.
   Текст поиска можно изменить вручную. При включении подбора прежние фильтры
   сбрасываются; источник берётся из выбранного поля формы.
2. Учитываются только confirmed-навыки и технологии confirmed-проектов. Синонимы
   нормализуются (JS → JavaScript, Postgres → PostgreSQL), дубликаты убираются.
   Для ограничения работы браузера используются первые 100 уникальных навыков;
   если есть ещё, интерфейс показывает число пропущенных.
3. В названии, описании и структурированных навыках вакансии ищутся упоминания
   технологий из явного словаря. Проверяются границы слов: Java не совпадает
   с JavaScript, Git не совпадает с GitLab. Для Go в свободном тексте нужен Golang;
   отдельное Go принимается из структурированного списка навыков.
   Навыки профиля вне словаря также ищутся по точному названию с границами слов.
4. Загруженная страница сортируется по числу совпадений, затем (если есть
   совпадения) по меньшему числу остальных упомянутых навыков. При равенстве
   сохраняется порядок источника. Объекты вакансий не изменяются.
5. На карточке видны совпавшие навыки и упоминания, которых нет в профиле.
   Формат работы сравнивается с предпочтением; неизвестный формат не считается
   несовпадением. Регион сравнивается по нормализованному названию: разные названия
   не доказывают географическую несовместимость, поэтому предлагается проверить условия.
6. В подробной карточке сравнение доступно тоже; профиль загружается заново.
   Возврат к списку сохраняет режим, поиск и страницу.

Подбор запускается и на реальном источнике «Работа России», и на явно обозначенном
демокаталоге. Не выполняются дополнительные LLM-запросы, не создаются эмбеддинги,
не требуется общий ключ проекта. Расхода квоты пользовательской модели нет.
Полный профиль и история интервью не отправляются источнику вакансий: передаётся
только обычный текст поиска (должность или навык), как при ручном поиске.

## Ограничения

- Оценивается только текущая загруженная страница, до 20 вакансий, а не весь рынок.
  Счётчик источника не является числом персонально подходящих вакансий.
- Это совпадения упоминаний, не вероятность найма и не проверка всех требований.
  Обязательные и желательные требования, отрицания, смысловой контекст и уровень
  владения технологиями автоматически не различаются. Название профессии не
  используется как доказательство наличия навыка.
- Словарь ограничен преимущественно IT-навыками; неперечисленные технологии
  могут остаться нераспознанными. Неуказанное в профиле не означает незнание.
- Город и формат работы сами не исключают вакансии и не влияют на сортировку.
  Жёсткие фильтры выбирает пользователь; условия проверяются в оригинале.
- Свежие правки профиля учитываются после повторного подбора/перехода в карточку.
- Извлечение требований моделью, эмбеддинги и оценка всего импортированного
  набора — последующие улучшения. Полный этап 6 этим изменением не закрывается.

## Проверка

Детерминированные тесты: синонимы, технологии проектов, исключение suggested/rejected,
границы слов и специальные символы, произвольный навык, неизвестные условия,
стабильная сортировка, ограничение размера профиля. Для 10 синтетических профилей
задан вручную ожидаемый первый результат среди пяти вакансий. Это небольшая
проверка порядка, а не полная оценка top-5 на реальном рынке.
Интерфейс проверяет авторизованную загрузку, отсутствие частичного подбора при
401/503, пустой профиль, поиск, сортировку и сохранение режима при навигации.
