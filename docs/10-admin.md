# Панель администратора

Путь: /admin. Ссылка появляется в личном профиле после входа администратора. Обычный пользователь получает 403 от admin API независимо от видимости ссылок; анонимный — 401.

## Функции

- Поиск пользователей по email, список с пагинацией (20 по умолчанию, максимум 100).
- Карточка: email, роль, статус, профиль и число активных сессий.
- Блокировка / разблокировка с обязательной причиной.
- При блокировке все сессии отзываются, повторный вход запрещается. После разблокировки нужен новый вход: старые сессии не восстанавливаются.
- Журнал: исполнитель, пользователь, действие, причина и время. Пароли, хеши и токены в admin API не выдаются.
- Администраторов блокировать нельзя, включая себя. Веб-интерфейс не назначает роли и не удаляет аккаунты.

## Назначение первого администратора

Миграция 0003 создаёт is_admin=false и is_blocked=false для всех существующих пользователей. Нет публичного bootstrap endpoint и правила «первый зарегистрированный становится админом».

Сначала владелец проекта явно выбирает уже зарегистрированный аккаунт приложения. Затем оператор с доступом к серверному DATABASE_URL выполняет из backend:

```sh
.venv/bin/python -m app.manage_admin --email chosen-account@example.com
```

Это пример адреса, не настоящий администратор. Не запускать команду для произвольного email и не передавать DATABASE_URL в командной строке или чат. Использовать уже настроенное серверное окружение. Команда не создаёт пользователя, не повышает заблокированный аккаунт и записывает operator_grant_admin в журнал. При повышении существующие сессии отзываются; после назначения нужно войти заново.

На Render Free shell может быть недоступен; назначение можно провести доверенным оператором через защищённое подключение к Neon после явного выбора аккаунта владельцем. Новое право не должно автоматически выдаваться email из переменной окружения: email в текущей версии ещё не верифицируется.

## API

| Метод | Путь | Назначение |
|---|---|---|
| GET | /api/admin/users?q=...&offset=0&limit=20 | Список и поиск |
| GET | /api/admin/users/{id} | Карточка пользователя |
| PATCH | /api/admin/users/{id}/block | blocked: true/false, reason: строка 3–500 символов |
| GET | /api/admin/events?limit=50 | Последние события, максимум 100 |

Все ответы admin API используют Cache-Control: no-store. Изменения защищены общей проверкой Origin. Роль и блокировка проверяются по БД при каждом запросе. Блокировка и вход сериализованы row-lock по пользователю. Изменение статуса и событие аудита сохраняются одной транзакцией.

## Проверки

PostgreSQL-тесты: запрет доступа анонимному и обычному пользователю; отсутствие повышения через register/profile; bootstrap выбранного аккаунта и отзыв старых сессий; безопасный список; поиск с буквальным %; карточка; защита админа; причина блокировки; отзыв сессий; запрет входа блокированному; разблокировка и новый вход; журнал. Frontend-тесты: отсутствие запроса списка без прав, вход, просмотр и блокировка с причиной.

## Границы версии

Нет удаления пользователей, смены чужого пароля и выдачи ролей через веб. Это отдельные операции с дополнительной проверкой прав и подтверждением. Журнал защищён правами приложения; он не является внешним неизменяемым аудитом.
