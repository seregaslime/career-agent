# Этап 2: вход и профиль

## API

| Метод | Путь | Назначение |
|---|---|---|
| POST | /api/auth/register | Email и пароль; создаёт пользователя, пустой профиль и сессию |
| POST | /api/auth/login | Email и пароль; создаёт новую сессию |
| POST | /api/auth/logout | Отзывает текущую сессию и удаляет cookie |
| GET | /api/auth/me | ID и email текущего пользователя; без входа 401 |
| GET | /api/profile | Только свой профиль |
| PATCH | /api/profile | Частичное обновление своих full_name, target_role, education, about |

Пароль: 12–128 символов. Email нормализуется; email verification и сброс пароля в эту итерацию не входят. Для учебной версии использовать отдельный пароль. Поля owner/user_id не принимаются в запросе профиля. Авторизация только по серверной сессии.

## Хранение и защита

Таблицы users, sessions, profiles создаёт миграция 0002_auth_profile. Пароли хешируются scrypt (N=16384, r=8, p=5, случайная соль), сессии — случайные 256-битные токены; в БД сохраняется только SHA-256 токена и срок 7 дней. Cookie: HttpOnly, Secure, SameSite=Lax, Path=/api. Локальный HTTP использует COOKIE_SECURE=false; production оставляет true. Logout отзывает токен в БД. Ограничитель входа/регистрации: 10 попыток в минуту по email и адресу клиента, пока рассчитан на один процесс; перед масштабированием нужно общее хранилище. Очистка истёкших строк сессий — отдельная будущая задача.

Mutating-запросы с Origin вне CORS_ORIGINS получают 403. Нет credentialed wildcard CORS. Приватные ответы не кешируются. Токен не хранится в localStorage и не возвращается в JSON.

## Один origin для браузера

Frontend вызывает относительный /api. В Cloudflare Pages requests проходят через frontend/functions/api/[[path]].ts к фиксированному backend Render. HttpOnly-cookie относится к домену frontend, поэтому вход не зависит от сторонних cookie. В dev работает Vite proxy, в локальном Compose — Nginx proxy. Proxy не принимает произвольный URL назначения и отключает кеширование; redirects от backend не следуются автоматически.

GitHub workflow при `wrangler pages deploy` автоматически собирает каталог functions. VITE_API_BASE_URL теперь не используется клиентом; API_BASE_URL остаётся для smoke-проверки backend в CI/CD. Backend hostname в proxy — публичная конфигурация, не секрет.

## Приёмка

1. Открыть /profile и создать синтетический аккаунт.
2. Заполнить имя, цель, образование и описание; сохранить.
3. Обновить страницу — профиль и вход сохранились.
4. Выйти — приватный профиль не отображается.
5. Войти снова — данные сохранились.
6. В отдельном браузерном профиле создать второго пользователя — данные первого недоступны.

Автотесты проверяют этот путь на временной PostgreSQL, cookie-флаги, хеширование, неверные пароли, expiry, logout, cross-origin mutation и попытку подменить user_id. Никогда не направлять TEST_DATABASE_URL на production.
